# SchemaForge

회로를 말로 설명하면 넷리스트·회로도·2층 PCB를 만들고, KiCad 설계 규칙 검사(DRC)까지 돌려서 `.net`, `.kicad_pcb`, 거버 파일로 내보내는 웹 앱.

![모터 드라이버 데모 회로로 생성한 2층 기판](public/home/motor-board.png)

위 이미지는 편집하지 않은 실제 출력이다. 저장소에 들어 있는 모터 드라이버 데모 회로(`server/test_circuits/nmos_motor.py`)를 돌린 결과로, 기판 36.7 × 36.4 mm, 배선 14/14 완료, 비아 3개, 트랙 길이 72 mm, KiCad DRC 오류 0이다. OpenAI 키 없이 `/?demo=motor`에서 같은 결과를 만들 수 있다.

배포 데모: https://schemaforge-app.duckdns.org/?demo=motor (집의 젯슨 서버, DEPLOY.md 7절). 예전 주소 https://schemaforge.kro.kr (Render 무료 인스턴스, 기본 주소 https://schemaforge-zuco.onrender.com 과 같은 서버)도 같은 코드로 남아 있는데, 15분 동안 아무도 쓰지 않으면 잠들어서 첫 접속에 약 1분 걸린다. 데모 기판 하나(넷리스트 → 기판·DRC)는 젯슨에서 2초, Render에서 6~9초 걸렸다(2026-11-08, `check_live.mjs` P2).

## 프로젝트 개요

### 배경
간단한 회로 하나를 기판으로 만들려 해도 회로도 작성 → 부품마다 풋프린트 고르기 → 배치 → 배선 → 설계 규칙 검사 → 거버 출력까지 KiCad 같은 전문 도구를 거쳐야 한다. 처음 배우는 사람에게는 도구 사용법이 회로보다 먼저 벽이 된다. 생성형 AI로 회로 코드를 만드는 것은 가능하지만, AI가 만든 결과를 그대로 기판으로 만들면 핀이 끊기거나 규칙을 어긴 기판이 나와도 알아채기 어렵다.

### 목표
- 말로 설명한 회로를 **제조에 쓸 수 있는 파일**(`.net`, `.kicad_pcb`, 거버)까지 한 화면에서 만든다
- AI가 만든 결과를 **검사로 확인한 뒤에만** 다음 단계로 넘긴다 — 회로는 실행과 회로 점검, 기판은 KiCad DRC
- 배치·배선이 계산되는 과정을 그대로 보여 줘, 결과가 어떻게 나왔는지 사용자가 따라갈 수 있게 한다

### 대상 사용자
- 회로 기초를 배우는 학생·입문자 — 아이디어를 기판까지 빠르게 확인하고 싶은 사람
- 작은 실험용 기판(LED, 타이머, 센서, 모터 구동)을 자주 만드는 메이커

### 주요 기능
| 기능 | 내용 |
|---|---|
| 말로 회로 만들기 | 한 줄 설명 또는 회로 종류(11종)에서 시작. 빠진 사양은 질문으로 채우고, 설계 계획을 확인한 뒤 생성 |
| 회로도와 대화형 수정 | 생성된 회로를 회로도로 보여 주고 "저항 추가", "R1 값을 100k로"처럼 말로 고친다. 요청에 이름이 없는 부품은 지우거나 값·연결을 바꾸지 못하게 막고, 고친 뒤에는 바뀐 연결선 수를 알려 준다 |
| 자동 배치·배선 | 실제 KiCad 풋프린트로 부품을 놓고(힘 기반 배치) 2층에 선을 긋는다(A* 경로 탐색). SMD·THT 선택 |
| 검사 | KiCad DRC + 회로 점검(전원 누락, 연결 안 된 핀, IC 전원 핀 옆 커패시터, 서로 이어지지 않은 두 접지). 결과를 숫자로 표시. DRC 줄을 펼치면 어떤 규칙으로 검사했는지와 앱 배선 규칙의 숫자를 제조사(JLCPCB) 최소값·출처·읽은 날과 함께 보여 준다. 회로도 단계에서는 안전 경고도 낸다: 모터·릴레이 역기전력 보호 다이오드, 전원 역접속 보호, 모터 비상정지 스위치 |
| 2D · 3D 보기 | KiCad 색 2D와 KiCad가 내보낸 3D 모델을 나란히 |
| AI 기판 다듬기 (선택) | AI가 배치·선 굵기 수정을 제안하고, 검사 점수가 좋아질 때만 반영 |
| 내보내기 · 부품 | `.net`, `.kicad_pcb`, 거버 zip(PCB 업체에 그대로 올리는 7개 층 + 도금·비도금 드릴, GND 동박 포함), 부품 목록(BOM: 같은 부품을 묶은 수량·패키지, CSV)과 Mouser 부품 검색. 측정표(기판의 테스트 포인트 위치와 전원을 켰을 때 나와야 하는 전압, 사람용 CSV·측정 장치용 JSON). 실제 주문·조립 순서는 [docs/fabrication-guide.md](docs/fabrication-guide.md) |

## 무엇을 하나

| 단계 | 하는 일 | 쓰는 것 |
|---|---|---|
| 회로 | 설명에서 부품과 연결을 정하고 skidl 코드를 실행해 넷리스트를 만든다. 넷리스트 점검(연결 안 된 핀 등)에서 오류가 나오면 모델이 한 번 고치고, 고친 코드가 실행되며 오류가 줄 때만 받아들인다 | GPT-4o, skidl, `server/erc_repair.ts` |
| 배치 | 부품마다 KiCad 풋프린트를 붙이고, 연결된 부품이 가까워지도록 자리를 잡는다 | 힘 기반 배치 (`server/pcb/placer.py`) |
| 배선 | 두 층에 트랙을 긋고, 막히면 비아로 층을 바꾼다. 전원 넷은 굵게 긋는다 | A* 경로 탐색 (`server/pcb/router.py`) |
| 마감 | GND 동박(pour), 고정 구멍 4개, 전원 넷 테스트 포인트를 넣는다 | `server/pcb/board.py` |
| 검사 | KiCad DRC와 회로 점검(전원 누락, 연결 안 된 핀)을 돌린다 | `kicad-cli`, `server/pcb/erc.py` |
| 다듬기 | 선택 사항. 모델이 배치·선 굵기 수정을 제안하고, **검사 수치가 좋아질 때만** 반영한다 | `server/ai_layout.ts` |

화면에서는 배치와 배선 과정을 그대로 재생하고, 완성된 기판은 2D(KiCad 색)와 3D(KiCad가 내보낸 GLB 모델)로 나란히 본다. **배치하기** 탭에서는 실물 기판에 부품을 올리면서 KiCad 3D 모델의 부품을 눌러 체크한다(평면 그림으로도 볼 수 있다). 옆 목록은 같은 부품끼리 묶고 진행률을 보여 주며, 목록에 마우스를 올리면 그 부품 자리가 빛난다. LED·전해 커패시터·555처럼 방향이 있는 부품은 처음 누르면 기판 위 정확한 패드에 +, −, 1 표시를 띄우고 실물에서 무엇을 보면 되는지 쉬운 말로 알려 준 뒤, '맞췄어요'를 눌러야 체크된다. 체크는 기판마다 이 브라우저에 남는다.

### AI 다듬기가 동작하는 방식

모델은 **제안만** 하고, 적용과 판정은 코드가 한다.

1. 기판 상태(부품 위치, 넷별 굵기, 지표, DRC 위반)를 모델에게 준다.
2. 모델이 이동·회전·선 굵기 변경을 제안한다.
3. 제안을 **선 폭 묶음 → 배치 묶음**으로 나눠, 묶음마다 따로 적용한다.
4. 묶음마다 겹침 사전 검사 → 재배선 → DRC → 점수 비교.
5. **나빠지거나 그대로면 되돌린다.** 좋아진 묶음만 남는다.

점수 순서: DRC 오류 → 미배선 → 겹침·기판 밖 → 디커플링 커패시터 거리(1 mm 이상 변하면 그것으로 판정, 소수 1자리로 보이게 늘면 거절) → 좁은 전원선 개수 → 선 길이(HPWL, 0.1 mm) → 비아 → 트랙 길이(0.1 mm) → 보이게 준 디커플링.

### 설계 원칙 — AI는 제안하고, 한계는 코드와 하드웨어가 지킨다

SchemaForge 전체가 같은 원칙으로 나뉘어 있다. AI(언어 모델)는 회로 코드와 배치 수정을 **제안**만 한다. 받아들일지, 되돌릴지, 통과인지는 정해진 코드(회로 실행, 회로 점검, 동작 검사, KiCad DRC, 위의 점수 비교)가 정한다. AI가 아무리 그럴듯하게 답해도 검사를 통과하지 못하면 다음 단계로 가지 않는다.

같은 생각을 만들어질 회로에도 적용한다. 회로 검사는 모터가 배터리까지 스위치 없이 이어져 있으면 "모터 비상정지 스위치가 없습니다"를 경고한다. 모터를 켜고 끄는 판단은 프로그램(마이크로컨트롤러)이 하더라도, 프로그램이 멈추거나 트랜지스터가 켜진 채 고장 나면 판단이 소용없다. 그때 모터를 멈추는 것은 사람이 누르는 스위치, 곧 하드웨어여야 한다. 전원 역접속 보호(전원을 거꾸로 꽂아도 직렬 다이오드가 막아 준다)도 같은 이유로 경고한다.

2026 창의적 종합설계 경진대회 본선(2026-11-13)에 나온 액체 자동 충진기 팀도 같은 구조를 썼다. 카메라와 비전 처리(젯슨)는 얼마나 내려가고 얼마나 채울지 측정·판단만 하고, 내려가는 한계와 비상정지는 마이크로컨트롤러 펌웨어와 하드 스톱(기구로 막는 멈춤 장치)이 최종 책임을 진다고 발표했다.

### 동작 검사 — 그 회로가 실제로 동작하는가

DRC와 회로 점검은 "연결이 이어져 있는가"까지만 본다. 동작 검사는 부품 값으로 계산해서 "값이 맞아 실제로 동작하는가"를 본다. 회로도 단계(PCB 생성 전)와 완성된 기판의 검사 목록에 같은 결과가 나온다. PCB 생성은 막지 않는다.

| 규칙 | 계산 |
|---|---|
| 전원 전압 | 배터리(직렬이면 순서와 상관없이 더함)와 레귤레이터 출력을 먼저 정하고 넷 이름은 그다음에 본다. 직렬 다이오드(역극성 보호)를 지나면 순방향 전압만큼 낮아질 수 있는 범위로 넘기고, 거꾸로 단 직렬 다이오드 뒤의 레일에는 전원이 없다. 이름과 실제 전압이 다르거나, 배터리가 거꾸로이거나, 단자가 떠 있거나, 전압이 다른 배터리가 병렬이거나, GND가 배터리와 이어져 있지 않으면 안 됨. 배터리 값에서 전압을 읽지 못하면(예: `2xAA`, `CR2032`) 판단 불가. 리튬이온 배터리(`4S`, `3S1P LiPo`, `7.4V Li-ion`, `11.1V 리튬`)는 셀 수를 읽어, 전압이 적혀 있지 않으면 셀당 공칭 3.6 V로 계산하고 완전히 충전한 전압(셀당 4.2 V, Panasonic NCR18650B·Murata US18650VTC6 데이터시트)도 함께 넘긴다 |
| 전원 단락 | 스위치를 누르거나 릴레이 접점이 붙을 때 서로 다른 전원이 바로 이어지는지, 두 전원 사이에 다이오드가 순방향으로 걸리는지 |
| LED 전류 | (전원 − 순방향 전압 합) ÷ 직렬 저항, 최대 전류와 비교. 직렬 LED, 저항 하나를 나눠 쓰는 병렬 LED(스위치로 꺼지는 LED가 있으면 가장 큰 전류는 남은 LED만 켜졌을 때로), 트랜지스터 뒤의 LED까지 계산. 방향이 거꾸로인지, 저항이 없는지(0 Ω 포함) |
| 보호 다이오드 | 릴레이 코일·모터 양단에 있는지, 캐소드가 전원 쪽인지(코일 전원보다 낮은 레일이면 꺼져도 전류가 흐르므로 안 됨), 역전압·전류 정격 |
| 릴레이 코일 전압 | 전원 − 스위치가 보장하는 최대 전압 강하가 동작 전압(정격의 75%) 이상인지, 허용 최대(130%) 이하인지. 거꾸로 단 보호 다이오드가 코일을 묶는지 |
| 트랜지스터 켜짐 | NPN: IC/IB 조건을 만족하면 VCE(sat) 행, 아니면 최소 hFE 행(VCE 1 V)으로 켜짐을 판단. 베이스에 저항이 없거나, 풀다운만 있거나, 저항 반대쪽이 떠 있으면 안 됨. MOSFET: 게이트 전압이 켜짐 저항 보장 전압 이상인지, 게이트 최대 정격(20 V, IRLZ44N은 16 V) 미만인지. 소스 아래 감지 저항이 있는데 부하 전류를 모르면 강하 0과 가장 큰 전류(ID 최대, 부하 전원 ÷ 감지 저항이 더 작으면 그 값) 두 끝을 계산해, 신호 하나라도 판정이 갈리면 판단 불가로 두고 어느 전류까지 켜지는지 적는다. 강하 0 쪽은 전류가 조금이라도 흐를 때로 보므로, 게이트가 보장 전압이나 문턱과 딱 같으면 못 미치는 것으로 센다. 게이트 풀다운이 없으면 부하 전류를 몰라도 경고한다. 감지 저항 강하가 구동 전압보다 커지는 계산은 음수 대신 0 V 이하로 적는다 |
| 스위치 전류 한계 | 부하 전류가 IC·ID 최대값 이하인지, 전원이 VCEO(NPN)·VDSS(MOSFET) 미만인지. 모터 전류와 정격 전압은 값에 적힌 것(예: `MOTOR 5V 0.3A`)을 읽고, 정격보다 높은 전압이 걸리면 안 됨(전류는 전압에 비례한다고 어림). 부하 전원이 0 V 이하면 안 됨. MOSFET 게이트는 부하로 세지 않음. IRFZ44N·IRLZ44N의 ID 최대는 케이스를 25 °C로 유지할 때의 값이라, 켜짐 저항 발열(I² × 게이트 전압에서 보장되는 RDS(on) 행 × 175 °C에서 커지는 배수, 데이터시트 그래프를 두 번 읽은 값 중 큰 쪽)이 방열판 없이 견디는 (175 − 25) °C ÷ RθJA 62 °C/W = 2.42 W의 90% 이상이면 경고(방열판은 계산하지 않음), 케이스를 25 °C로 유지할 때의 최대 손실(PD) 이상이면 안 됨. RDS(on) 행은 게이트 전압 이하에서 보장된 것 중 가장 작은 값(IRLZ44N: 10 V 22 mΩ, 5 V 25 mΩ, 4 V 35 mΩ)이고, 게이트가 가장 낮은 보장 전압보다 낮으면 켜짐 저항을 몰라 판단 불가(트랜지스터 켜짐 결과에서 이어진 것으로 머리글에 한 번만 셈) |
| 저항 발열 | LED·컬렉터 부하·베이스와 게이트 저항·이미터/소스 아래 전류 감지 저항·전원 사이 저항·555 출력에 달린 저항·모터와 직렬인 저항·555 타이밍 저항의 전력이 정격 이하인지. 감지 저항은 부하 전류(NPN은 베이스 전류도)로 P = I² × R, 부하 전류를 모르면 트랜지스터 정격 전류(부하 전원 ÷ 감지 저항이 더 작으면 그 값)로 계산하고, 그래도 정격의 90% 미만이면 통과, NPN 베이스 전류만으로 90% 이상이면 경고나 안 됨, 그 밖에는 판단 불가로 두고 어느 전류 미만이면 되는지 적는다. 비안정 555의 RA는 VCC가 걸리는 방전 구간 비율 RB ÷ (RA + 2RB)로 평균을 낸다 |
| 극성 커패시터 방향 | 전해 커패시터의 + 단자가 − 단자보다 높은지 |
| 555 타이머 | 전원 4.5~16 V, GND·RESET·CTRL·DISCH 배선, 출력(3번 핀)이 전원·GND에 바로 묶였는지, 비안정 구성이면 f = 1.44 ÷ ((RA + 2RB) × C) (병렬 저항·커패시터 합성), RA + RB 최대값은 VCC에 따라 |
| 레귤레이터 전압 | 입력 − 출력이 최소 전압 차 이상인지, 최대 입력(리튬이온 배터리면 완전히 충전한 전압으로도: 4S 16.8 V는 AMS1117의 15 V를 넘어 안 됨), 출력 커패시터, 출력 단락·입출력 바뀜·우회 |

- 계산 방향을 질문에 맞춘다. "전류가 너무 큰가"는 가장 작은 전압 강하(트랜지스터 0 V, 555 출력 강하 0 V, 직렬 다이오드 0 V, 코일 저항 −10%)로, "동작하는가"는 데이터시트가 보장하는 가장 큰 강하(감지 저항 강하, 직렬 다이오드 순방향 전압 최대 포함)로 계산한다. 555 출력이 받아 내리는 LED는 LOW 전압(VOL) 자료가 없어 가장 큰 전류만 계산한다. 절대 최대 정격은 같은 값이면 안 됨, 90% 이상이면 경고다.
- 스위치는 눌린(닫힌) 상태로, 릴레이는 붙은 상태(COM–NO 닫힘, NC 열림)로 계산한다. LED 직렬 경로도 닫힌 스위치·접점을 지나 이어 간다. 다만 릴레이 코일(붙는지, 보호 다이오드)은 자기 접점이 붙기 전 상태로 계산하고(자기 접점으로만 전원을 받는 코일은 붙지 못한다), 코일 핀이 비어 있는 릴레이는 붙지 않는 것으로 본다. 닫힌 접점이 레귤레이터 출력에 다른 전원을 이으면 출력 전압을 바꾸지 않고 단락으로 본다. 저항으로 끌어올린 넷을 GND로 내리는 버튼(555 리셋 버튼 등)은 입력으로 보고 버튼을 놓았을 때 동작하는지를 본다. 풀업 없이 GND로만 내리는 리셋 버튼은 놓으면 핀이 떠 있으므로 경고다.
- 결과는 **동작함 / 경고 / 안 됨 / 판단 불가** 네 가지다. 커넥터로 들어오는 전원이나 모터 전류처럼 계산에 필요한 값을 모르면 통과로 처리하지 않고 판단 불가로 둔다. 신호 전압을 모르면 3.3 V와 5 V 두 경우를 계산해 보여 준다. MCU는 커넥터로만 들어오므로, 게이트·베이스를 구동하는 커넥터의 값이 보드나 칩, 전압을 밝히면(ESP32·ESP8266·STM32·RP2040·Pico·3V3은 3.3 V, Arduino Uno·Nano·Mega·ATmega328·5V는 5 V, Nano ESP32·Nano 33·Jetson Nano처럼 칩이 3.3 V면 3.3 V) 그 전압 하나로 계산하고 판정 근거에 어느 커넥터 값에서 왔는지 적는다. 신호가 지나는 넷 이름에 VCC_3V3·3V3_OUT처럼 3.3 V만 적혀 있으면 보드 이름보다 그 전압을 먼저 쓴다. 넷 이름의 5V(PWM_5V 등)는 부하의 전압일 때가 많아 신호 전압을 올리는 데 쓰지 않는다. 보드 없이 ATmega328 칩만 적힌 값은 3.3 V로도 도는 칩이라, 같은 커넥터의 전원 핀이 모두 3.3 V나 5 V 하나로 알려져 있으면 그 전압으로, 그 밖에는(전원 핀이 없을 때도) 두 경우를 계산한다. Uno·Nano·Mega는 보드 이름 그대로일 때만 5 V로 읽는다(앞에 Arduino, 뒤에 R3·2560 같은 판 번호나 D9 같은 핀 이름만). UNO Q·Nano Matter·Orin Nano처럼 다른 낱말이 붙으면 3.3 V 보드일 수 있어 두 경우를 계산한다. 전원 커넥터(PWR)와 두 전압을 다 적은 값은 신호로 읽지 않는다. 5V·3V3처럼 적힌 전압은 그 커넥터의 다른 핀이 GND가 아닌 넷 중 전압을 아는 넷, 이름이 전원인 넷(+5V 등), 또는 트랜지스터의 베이스·게이트(바로나 저항 하나를 거쳐) 말고 다른 것(부하, 다른 전원 핀)에 이어진 넷에 있거나(넷 이름이 VM·V+여도) 값에 VIN·USB 같은 전원 낱말이 있으면 전원의 전압이라 신호로 읽지 않는다. 머리글은 한 원인에서 이어진 실패를 한 번만 세고, 판단 불가 개수를 함께 보여 준다. 회로 검사에 오류(끊긴 연결 등)가 있으면 이어진 부분만 통과한 것이라 머리글은 통과 대신 '판단 불가 · 회로 오류'로 보인다. 릴레이는 모두 놓인 상태(COM–NC 닫힘, COM–NO 열림)에서 시작해 실제로 붙는 릴레이만 바꿔 가며 계산한다(서로를 붙잡기만 하는 래치는 시작하지 않는다). 붙는 릴레이의 NC 쪽은 놓여 있을 때로 따로 본다. 붙지 않는 릴레이 접점에 기대는 판정은 그 릴레이를 원인으로 묶고, 접점이 닫혀도 남는 오류는 따로 센다. 트랜지스터 구동 실패는 LED를 정격 전류로 바꿔도 실패할 때만 트랜지스터 자체의 문제로 센다.
- 핀 대응 정보(`pad_pins`)가 없는 예전 보드는 핀을 구분할 수 없어 동작 검사를 하지 않고 판단 불가 한 줄만 낸다.
- 한계값은 모두 제조사 데이터시트에서 읽고 출처를 함께 적었다 (`src/lib/partSpecs.ts`: Kingbright LED, Vishay 1N4148·1N4007, onsemi 1N5819, onsemi 2N3904·MMBT3904·BC547·2N7002·2N7000, Infineon IRFZ44N·IRLZ44N, TI NE555·LM7805, AMS1117, Sanyou SRD 릴레이, Yageo 저항). 결과 화면에서 각 판정을 펼치면 계산식과 출처가 보인다.
- 되는 회로와 안 되는 회로를 한 쌍씩 넣어 두었다. 키 없이 비교할 수 있다: `/?demo=led` ↔ `/?demo=led_bad` (저항 680 Ω → 10 Ω), `/?demo=relay` ↔ `/?demo=relay_bad` (보호 다이오드 반대 방향), `/?demo=ne555` ↔ `/?demo=ne555_bad` (전원 9 V → 3 V).

## 필요한 것

- Node.js, Python (개발·검사 환경: Node 24.14, Python 3.14)
- **KiCad** — DRC, 거버, 3D 모델 내보내기에 `kicad-cli`가 필요하다 (확인한 버전 10.0.6). 없어도 기판 생성과 화면 표시는 되지만 검사·내보내기는 꺼진다 (`/health`가 어느 쪽인지 알려 준다)
- OpenAI API 키 — 회로 생성과 AI 다듬기에 쓴다. 없으면 내장 데모 회로 4개로만 돌린다

## 실행

```bash
npm install
pip install -r requirements.txt
cd server && npm install && cd ..
```

`server/.env`에 키를 넣는다 (`.env`는 커밋하지 않는다).

```
OPENAI_API_KEY=...
SUPABASE_URL=...            # 로그인·세션 저장 (없으면 메모리에만 저장)
SUPABASE_SERVICE_KEY=...
MOUSER_API_KEY=...          # 부품 가격·재고 조회 (선택. 없으면 BOM에 줄마다 검색 링크만 보인다)
KICAD_CLI_PATH=...          # kicad-cli가 PATH에 없을 때
```

```bash
npm run dev      # 화면(vite 3000) + API(8113) 동시 실행
```

Windows는 포트를 100개씩 묶어 자기 몫으로 잡아 둘 수 있고(Hyper-V·WSL, 재부팅하면 바뀔 수 있다), 그 안의 포트는 `EACCES`로 열리지 않는다. 개발 PC에서 8080과 8002가 그랬다(7989-8088). API가 `Cannot listen on port`로 끝나면 `netsh interface ipv4 show excludedportrange protocol=tcp`로 범위를 보고, 그 밖의 포트를 `server/.env`의 `PORT`에 적는다.

`http://localhost:3000` 접속. 키 없이 보려면 `http://localhost:3000/?demo=motor` (다른 데모: `led`, `ne555`, `relay`, 일부러 망가뜨린 `led_bad`, `ne555_bad`, `relay_bad`).

## 검사

`npm test`가 아래 검사 중 모델 없이 도는 것을 모두 차례로 돌린다 (깨끗한 체크아웃에서 대략 8분, KiCad 필요). 앞 검사가 실패하면 거기서 멈춘다. 브라우저로 화면을 쓰는 검사(`npm run test:browser`가 따로 돌린다), 배포 이미지 검사(Docker), 배포된 서버 검사는 넣지 않는다. 어느 검사가 어느 쪽인지는 `scripts/check_test_chain.ts`가 목록으로 지킨다. 기판을 읽는 검사가 쓰는 검사용 기판은 `scripts/make_check_boards.ts`가 데모 회로 4개를 SMD·THT로 만들어 `server/outputs/`에 기판마다 그 넷리스트와 함께 둔다(없거나 생성기보다 오래됐을 때만).

```bash

AI가 선 이름을 빼먹어도 적은 핀이 이미 있는 선으로 합치는지, 이미 연결돼 있던 핀을 옮기면 알리는지, 요청 문장이 가리키지 않은 부품은 AI가 핀을 다른 선으로 옮기거나 지우거나 값을 바꿔도 적용하지 않고 그 부품을 알리는지(2026-10-30 555 회로의 두 사례: 배터리 + 쪽이 VCC에서 떨어진 것, C4를 넣으며 다른 부품 핀 4개를 옮긴 것. 부품은 기호로, 또는 회로에 하나뿐인 종류 이름으로 가리킨다("LED 빼줘"). 같은 종류를 추가하는 편집이면 종류 이름은 새 부품을 가리킨다. 선 이름만 통째로 바꾸기와 비어 있던 핀 잇기는 그대로 적용), AI가 먼저 묻는 답("이 연결을 적용할까요?")에 편집이 딸려 와도 적용하지 않고 아직 안 바꿨다고 알리는지(되물을 답에는 바뀔 부품 기호를 넣어 권한다), 바뀐 것이 없는 답에는 회로가 바뀌지 않았다고 맨 앞에 덧붙이고 동작 칩을 남기지 않는지(막힌 부품이 있거나 묻는 답이어도), 이미 있는 기호로 넣으려다 건너뛴 부품의 연결을 그 기호의 기존 부품에 걸지 않는지, 정답을 모르는 해결 문장은 짐작하지 말고 묻게 하는지, AI 편집이 핀을 이름으로 적어도(K, −, p2) 번호로 받는지, 해결책마다 AI 편집에 넣을 문장이 있는지, AI 편집의 선 연결이 같은 이름의 기존 선에 합쳐지는지(핀 하나짜리 선을 새로 만들지 않음), Code 탭에 넣는 고칠 줄의 위치, 555 RESET은 VCC 핀과 같은 선으로, 끊긴 LED K와 한 핀짜리 GND는 하나의 해결책으로(기판 패드가 아닌 기호 핀 번호), 같은 부품 양끝은 제안하지 않음, LED 저항 추천값을 동작 검사로 다시 확인(SMD 470 Ω, THT 270 Ω, 전류만 보고 고른 330 Ω은 발열로 걸러짐), 핀 배열 경고의 다시 만들 방식, 모터 데모 경고의 해결 문구, 자리가 없는 다리 경고를 부품마다 하나로 묶고 다리 수만 말하는지(패드·핀 번호·넷 이름 없이, 다리 많은 다이오드는 브리지 정류기로 안내, 핀 이름 표에 없는 이름으로 저장된 연결도 같은 항목으로), 회로 검사에 오류가 있으면 동작 검사 칩과 패널이 '통과' 대신 판단 불가로 보이는지(LED를 뺀 555 회로), AI 편집으로 더한 부품이 다른 부품과 띄운 빈 자리에 놓이고 기존 부품은 자리를 지키는지(화면 안에 자리가 있으면 화면 안에, 없으면 화면 모양에 따라 옆 열이나 아래 줄에), 되돌리기로 돌아온 부품(종류와 연결이 같은 부품)이 다른 부품이 차지하지 않은 한 원래 자리로 가는지, 다른 탭에 갔다 오면 회로도가 겹친 부품까지 그대로인지, 이름 없는 연결 칩이 "+연결 C4"로 부품을 보이고 다른 부품과 이어지지 않은 새 부품을 알리는지, AI 편집 뒤 만든 기판의 넷리스트를 Netlist 탭과 .net이 주는지, Guide 탭이 AI 편집 전 회로 기준이라고 밝히는지, 회로 검사의 "LED 저항 없음"이 LED 줄을 따라가는지(직렬 LED, 저항-스위치-LED, 저항을 나눠 쓰는 병렬 LED, 보호 다이오드나 출력에 커패시터가 달린 스위치 너머의 저항은 통과, 색과 상관없이 저항이 없으면 오류, 이름으로 저장된 핀(A, K, +, −)은 핀 이름 표로 읽고 표에 없는 이름은 짐작하지 않음), AI 편집으로 더한 부품이 템플릿 이름으로 저장되는지(이름이 없으면 값의 단위로, 하나로 정해지지 않는 이름은 그대로 두어 풋프린트 없음으로 보고), 동사 "나요"로 끝나는 문장을 질문으로 읽지 않는지, 핀 없는 선 연결이 아무것도 바꾸지 않는지, 회로도와 PCB 간이 보기가 넷 도우미(`src/lib/nets.ts`)를, 저장 결과와 브라우저 저장소 읽기가 `src/lib/storage.ts`를 하나씩만 쓰는지(복사본이 갈라져 V33 같은 넷을 한쪽만 전원으로 봤다), 적용된 AI 편집 아래에 바뀐 연결선 수(새로 생김·달라짐·없어짐, 이름이 아니라 핀으로 비교해 이름만 바꾼 선은 0)가 넷 이름 없이 나오는지. 고칠 줄은 skidl·ERC·자동 수정 판정으로 따로 돌려 확인했다.

## 알려진 제약

- 2층 기판만 만든다. 기판 외형은 직사각형 고정.
- **데모 기판을 그대로 제작하지 마세요.** 릴레이 데모의 `Q1=2N3904`는 SMD 선택 시 MMBT3904용 패드 배열(1=B, 2=E, 3=C)로, 모터 데모의 `Q1=2N7002`는 THT 선택 시 2N7000용 배열(1=S, 2=G, 3=D)로 배선됩니다. 선택한 실제 부품과 기판의 핀 배열을 반드시 대조하세요. [2N3904/MMBT3904 데이터시트](https://www.onsemi.com/download/data-sheet/pdf/pzt3904-d.pdf), [2N7000/2N7002 데이터시트](https://www.onsemi.com/download/data-sheet/pdf/nds7002a-d.pdf).
- 모터 데모 주석의 2 A는 **검증된 구동 정격이 아닙니다.** 위 onsemi 데이터시트의 2N7002 연속 드레인 전류 최대값은 115 mA, 2N7000은 200 mA로, 2 A 부하에 사용할 수 없습니다. MOSFET·저항·다이오드·커넥터를 실제 모터 전류에 맞춰 재선정해야 합니다.
- 동작 검사는 전원·LED·보호 다이오드·릴레이·트랜지스터(로우사이드 NPN·N-MOSFET)·저항 발열·전해 커패시터·555·레귤레이터만 계산한다. 하이사이드 스위치, 555 방전 핀 전류와 출력 LOW 전압(한계값을 아직 확인하지 못함), 커패시터 내압은 보지 않는다. 그 밖의 부품 값(필터 커패시터 용량 등)과 555 주파수가 요청한 값과 맞는지는 보지 않으니 제작 전에 직접 검토해야 한다. 7805 외의 78xx 레귤레이터와 흰색·RGB·두 색 LED는 데이터시트 수치를 아직 넣지 않아 판단 불가로 나온다. 리튬 배터리는 리튬이온(셀당 4.2 V 충전)만 읽고, LiFePO4·LiHV처럼 충전 전압이 다른 셀은 적힌 전압 그대로 계산한다. LED는 빨강·초록·노랑·파랑만 같은 Kingbright 계열(5 mm WP7113, 0805 APT2012)의 데이터시트 값으로 계산한다.
- IRFZ44N·IRLZ44N은 동작 검사의 부품표에만 있다. 둘 다 TO-220(1=G, 2=D, 3=S, 탭=D)인데 기판의 N-MOSFET 자리는 SOT-23(2N7002)·TO-92(2N7000)뿐이라 그대로 맞지 않는다. 연속 전류 정격(49 A·47 A)은 케이스를 25 °C로 유지할 때의 값이라, 동작 검사는 방열판 없이 주위 25 °C에서 견디는지만 대략 계산한다(IRLZ44N은 게이트 4 V 이상에서 대략 5.54 A, 5 V 이상에서 6.55 A, 10 V 이상에서 6.99 A, IRFZ44N은 10 V 이상에서 대략 7.51 A까지). 게이트가 가장 낮은 보장 전압(IRLZ44N 4 V, IRFZ44N 10 V)보다 낮으면 발열은 판단 불가다. 방열판과 더 더운 주위는 계산하지 않는다. 175 °C에서 켜짐 저항이 커지는 배수는 데이터시트 그래프(일반값·최대값 표시 없음)를 두 번 읽고, 두 번째 읽기의 오차 범위 중 위쪽 끝을 쓴다(IRFZ44N 2.3배와 2.39배, 범위 2.35~2.45배 → 2.45배. IRLZ44N 2.2배와 2.23배, 범위 2.20~2.25배 → 2.25배).
- 역접속 보호와 모터 비상정지 경고는 연결만 따라가 보는 경고다. 배터리 또는 이름에 전원(PWR·DC·VIN·BAT 등)이 들어간 커넥터를 전원으로 보고, 모터는 값에 MOTOR나 모터가 들어간 커넥터만 안다. 다이오드와 스위치의 전류 정격, P-MOSFET 방식의 보호, 퓨즈는 보지 않는다(퓨즈와 P-MOSFET은 아직 부품 틀이 없다). 데모 회로 4개 중 3개(모터·555·릴레이)은 보호 부품이 없어 이 경고가 나온다.
- 배선은 격자 기반이라 트랙 각도가 제한된다.
- AI 다듬기는 한 번 돌 때마다 OpenAI 호출 비용이 든다. 기본은 꺼져 있다.

## 배포

Render 무료 인스턴스(`render.yaml`) + Supabase 기준 순서는 [DEPLOY.md](DEPLOY.md) 참고. 컨테이너에 KiCad가 없으면 DRC·거버·3D가 비활성화된다.

- KiCad 버전은 이미지마다 고정한다. Render 이미지는 10.0.5(`Dockerfile`의 `kicad/kicad:10.0.5`), 젯슨 이미지는 10.0.8(`Dockerfile.jetson`의 `KICAD_EXPECT`: PPA에서 다른 판이 오면 빌드가 멈추고, `scripts/jetson_run.sh`는 `/health`가 그 판을 말해야 뜬 것으로 본다). 같은 회로라도 두 서버의 거버가 바이트까지 같지는 않을 수 있다.
- 배포 서버(`NODE_ENV=production`)에서는 데모·기판·거버는 누구나 쓰고, 회로 생성·AI 편집·코드 실행은 `ALLOWED_EMAILS`에 있는 계정만 쓴다 (DEPLOY.md 0절).
- 무료 인스턴스는 CPU 0.1 · 메모리 512 MB다. 같은 제한(`--cpus=0.1 --memory=512m`)으로 묶은 로컬 컨테이너에서 데모 5개와 화면 시험이 통과했고, 데모 하나(넷리스트 → 기판·DRC → 3D → 거버)에 대략 40~60초 걸렸다. 15분 동안 요청이 없으면 잠들고, 다음 요청에 깨는 데 약 1분 걸린다 ([Render 무료 인스턴스](https://render.com/docs/free)).
- 이미지는 약 4.3 GB(압축 전, gzip 약 0.97 GB)로 KiCad 공식 이미지가 대부분이다.

SchemaForge 프로젝트 진행상황 (2026-10-28)

1. 프로젝트 요약

회로를 말로 설명하면 넷리스트, 회로도, 2층 PCB, KiCad 설계 규칙 검사(DRC), 거버 파일까지 만드는 웹 앱입니다.
저장소: https://github.com/gkdmsgus/SchemaForge
배포 주소: https://schemaforge-zuco.onrender.com (로그인 없이 체험: https://schemaforge-zuco.onrender.com/?demo=motor)

2. 일정 대비 진행

계획서는 10월 14일부터 12월 15일까지 9주 일정입니다.

1주차(10-14 ~ 10-20) 기판 2D·3D 화면 개선과 트랜지스터 핀 배열 문제: 완료했습니다. KiCad 3D 모델에서 부품을 눌러 배치를 체크하는 화면과, LED·전해 커패시터처럼 방향이 있는 부품의 극성을 패드 위에 표시하는 기능을 넣었습니다. 핀 배열 검사를 포함한 기판 8개 × 19항목 검사가 통과합니다. 다만 데모 회로의 부품 값과 기판 패드 배열이 다를 수 있는 경우는 아직 경고로 알리는 단계입니다.

2주차(10-21 ~ 10-27) 실제 배포: 완료했습니다. Railway 체험 기간이 끝나 Render 무료 인스턴스로 옮겼습니다. 10월 23일 배포 주소에서 데모 → PCB → 3D → 거버 내려받기 화면 시험 7개와 데모 기판 5개(DRC 오류 0, 미배선 0)가 통과했습니다.

3주차(10-28 ~ 11-03) 로그인 후 전체 흐름 점검: 이번 주에 시작합니다.

3. 이번 기간에 한 일

10월 14일 이후 커밋 89개를 올렸습니다.

- 동작 검사: 전원, LED, 릴레이, 트랜지스터, 555, 레귤레이터를 데이터시트 수치로 계산해 회로가 실제로 동작하는지 판정합니다(검사 184항목).
- 넷리스트 점검 자동 수정: AI가 고친 회로 코드를 서버가 다시 실행하고, 오류가 줄어들 때만 받아들입니다.
- 화면 기능: Code 탭, 부품표(BOM, CSV 내보내기, Mouser 검색 링크), 배치하기 탭, 방향 확인을 추가했습니다.
- 경고 해결책: 자주 나오는 경고마다 해결 방법을 붙이고, 해결 버튼을 누르면 AI 편집기에 수정 지시가 들어가게 했습니다. 실제 모델(gpt-4o-mini)로 10회 시험해 LED·555 예제의 연결 오류가 0개로 줄어드는 것을 확인했습니다.
- 공개 배포 전 보안: 로그인 없이 서버에서 코드가 실행되거나 AI가 호출되던 경로와, 서버 파일이 내려받아지던 경로를 막았습니다.

4. 검증

- 모델 없이 도는 자동 검사(npm test) 375항목이 통과했습니다(10-20 기준). 기판 8개 × 19항목(DRC 포함)도 통과합니다.
- 배포 환경과 같은 제한(CPU 0.1, 메모리 512 MB)으로 묶은 컨테이너에서도 데모 기판 5개와 화면 시험 7개가 통과했습니다.

5. 문제와 대응

- 무료 서버라 느립니다. 데모 하나에 35~41초가 걸리고, 15분 동안 쓰지 않으면 첫 접속에 약 1분이 걸립니다.
- 짧은 주소 schemaforge.kro.kr은 GitHub Pages로는 HTTPS 인증서 발급이 실패했습니다. Render 설정 파일로 도메인을 직접 연결해 https://schemaforge.kro.kr 로 열리게 했습니다.
- 대상이 애매한 수정 요청에서는 AI가 짐작해 맞는 연결을 바꾸는 경우가 있었습니다. 바뀐 연결을 채팅에 알리고 되돌리기 버튼을 안내하도록 했습니다.
- 데모 기판은 제작용이 아닙니다. 트랜지스터 핀 배열과 모터 전류 정격을 실제 부품에 맞춰 다시 골라야 합니다.

6. 다음 계획

- 3주차: 배포 서버에 로그인(Supabase)과 허용 계정을 설정하고, 회로 종류 5개 이상으로 설명 → 질문 → 계획 → 회로 → PCB → 거버 전체 흐름을 점검합니다.
- 4주차 이후: ESP32·레귤레이터 테스트 회로 추가, AI 다듬기 효과 측정, 실제 PCB 1회 주문, 사용자 테스트 순서로 진행합니다.
